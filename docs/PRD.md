## 1. 제품 개요 및 전체 모듈 맵

### 1.1 제품 개요
AI 컴패니언 로봇은 이동형 돌봄 로봇과 충전·종합 설정용 터치스크린 키오스크 콘셉트로 구성된 고령자 생활 지원 소프트웨어이다(B2C 월 43,900원 렌탈 패키지 모델 기준). 본 문서는 기존 1~4단계 코어 프로토타입 위에 확장되는 모듈 중 **3번 모듈(Smart Home Control)**의 제품 요구사항을 정의하며, 타 모듈과의 결합 규칙은 [MODULE_INTEGRATION_GUIDE.md](MODULE_INTEGRATION_GUIDE.md)를 따른다.

### 1.2 전체 모듈 구성 현황

| 구분 | 모듈명 | 주요 역할 (UML 기준) | 현재 상태 및 비고 |
| :--- | :--- | :--- | :--- |
| **1. 기존 로봇 코어** | Core (`Robot`, `IntentClassifier`, `Navigator`, `MedicationManager`, `AlertService`, `JsonStore`) | 음성/텍스트 대화, 프로필 관리, 복약 알림, 실내 경로 안내, 가상 낙상/거리/터치 감지 | 구현 완료 (`companion_robot.py`). **복약 리마인더 고도화**(`medications` DI) 및 **Ollama 챗봇**(`ai_model` DI)은 코어 결합 없이 교체 확장 가능하도록 인터페이스 경계 확보 |
| **2. 구현 완료** | Family Memory Archive (`memory_archive/`) | 가족 기억 저장·검색(SQLite) 및 대화창(`memory_search`)·GUI 7단계 탭 연동 | **프로토타입 구현 완료** (RAG/pgvector는 향후 확장) |
| **3. 구현 완료 (본 문서 중점)** | **Smart Home Control** (`smart_home/`) | **가스불 차단기(가스밸브) 상태 조회·차단 시뮬레이션, 장애 Fail-Safe 및 제어 어댑터 구조** | **구현 및 통합 완료** (`5단계 · 스마트홈` 탭 + 대화 의도) |
| **4. 구현 완료** | Health Monitoring (`health_monitor/`) | 심박·산소포화도 수집, 이상 징후 시연 입력(`MockWearable`), 역할별 로컬 알림, 대화(`health_check`) 연동 | **프로토타입 구현 완료** (실기기 BLE 연동은 향후 확장) |
| **5. 향후 확장 예정** | Family & Visitor Recognition | 가족/방문자 인식 및 보호자 알림 생성 | 향후 확장 예정 (`visitor_recognition/` 예약) |

## 2. 사용자 페르소나 및 핵심 유스케이스

### 2.1 주요 페르소나
1. **고령자 사용자 (Primary)**: 스마트폰이나 작은 메뉴 탐색보다 "가스불 꺼졌어?", "가스 잠가줘" 같은 자연어 발화나 키오스크의 크고 직관적인 버튼 조작을 선호한다.
2. **원격 보호자 / 가족 (Secondary)**: 기기 이상, 장시간 가스 개방, 차단 실패 시 생성되는 알림 기록을 통해 위험 상황을 즉시 파악하고자 한다.

### 2.2 핵심 유스케이스 (`UC-SH-01` ~ `UC-SH-05`)

| ID | 유스케이스명 | 사전 조건 | 기본/예외 흐름 | 사후 조건 |
| :--- | :--- | :--- | :--- | :--- |
| **UC-SH-01** | 가스밸브 현재 상태 조회 | 로봇 및 스마트홈 제어기 초기화 완료 | 사용자가 대화창에 "가스불 확인해줘" 입력 또는 스마트홈 탭에서 상태 조회 선택 → 제어기가 기기/제어 어댑터에서 최신 상태(`OPEN`/`CLOSED`/`ERROR`/`OFFLINE`) 조회 후 쉬운 문장으로 응답 | 현재 상태 및 마지막 갱신 시각 표시 |
| **UC-SH-02** | 가스밸브 차단 요청 | 가스밸브 상태가 `OPEN` | 사용자가 "가스불 꺼줘" 발화 또는 UI `가스 차단` 버튼 클릭 → 제어기가 기기 및 차단기 어댑터에 `SHUT_OFF` 명령 전달 → 밸브 상태 `CLOSED` 전환 및 `AlertService` 로그 기록 | 가스밸브 `CLOSED`, 차단 완료 안내 및 알림 로그 저장 |
| **UC-SH-03** | 이미 차단된 상태 중복 차단 (멱등성) | 가스밸브 상태가 `CLOSED` | 사용자가 다시 `가스 차단` 요청 → 제어기가 불필요한 오류를 내지 않고 "이미 가스밸브가 잠겨 있습니다"로 안전하게 응답 | 상태 `CLOSED` 유지, 정상 완료 처리 |
| **UC-SH-04** | 장시간 개방 감지 및 경고 | 가스밸브 `OPEN` 상태 및 개방 경과 시간 ≥ 임계치(기본 30분, 시뮬레이션 설정 가능) | 안전 점검(수동 점검 버튼 또는 주기적 체크) 시 임계치 초과 확인 → 사용자에게 차단 권유 안내 + `AlertService`에 경고 기록 생성 | 경고 알림 로그 저장 및 UI 경고 표시 |
| **UC-SH-05** | 차단기 통신 오류 / 차단 실패 (Fail-Safe) | 제어 어댑터 장애 모드 활성화 또는 기기 `OFFLINE`/`ERROR` | 상태 조회 또는 차단 요청 중 통신 오류/명령 실패 발생 → 예외를 삼키거나 크래시하지 않고 안전 오류 메시지 반환 + `AlertService`에 긴급/주의 알림 기록 | 앱 정상 동작 유지, 장애/미차단 경고 로그 저장 |

## 3. 기능 요구사항

### 3.1 Smart Home Control (`FR-SH` — 3번 개발자 구현 대상)

| ID | 관련 BR | 요구사항 명세 | 우선순위 |
| :--- | :--- | :--- | :--- |
| **FR-SH-01** | `BR-02`, `BR-05` | **스마트기기 공통 인터페이스**: 모든 스마트홈 기기가 구현해야 하는 공통 추상 인터페이스(`상태조회`, `명령처리`)를 정의한다. | High |
| **FR-SH-02** | `BR-02`, `BR-03` | **IoT 가스밸브 상태 모델**: 가스불 차단기(가스밸브)는 열림(`OPEN`), 잠김(`CLOSED`), 차단중(`SHUTTING_OFF`), 오류(`ERROR`), 오프라인(`OFFLINE`) 상태와 `차단상태(bool)`, 마지막 갱신 시각, 개방 경과 시간(시뮬레이션용)을 관리한다. | High |
| **FR-SH-03** | `BR-02` | **가스밸브 차단 제어**: `스마트홈제어기`는 대상 가스밸브를 조회해 차단 명령을 실행하고, 성공/실패 여부·변경 전후 상태·안내 메시지를 구조화된 결과 객체로 반환한다. 이미 차단 상태인 경우에도 안전하게 성공(변경 없음)으로 처리한다. | High |
| **FR-SH-04** | `BR-02` | **장시간 개방 감지 시뮬레이션**: 가스밸브가 열림 상태로 설정 임계 시간(기본 30분) 이상 유지된 경우 장시간 개방 위험을 판정하고 `AlertService` 경고 이벤트를 생성한다. | Medium |
| **FR-SH-05** | `BR-04` | **가스불 차단기 제어 어댑터 & Mock 시뮬레이터**: 가스불 차단기 제어 연동 계층을 추상 어댑터 인터페이스로 분리하고, 네트워크 없이 테스트·데모 가능한 로컬 Mock 시뮬레이터를 기본 구현한다. *(범용 다중 스마트홈 플랫폼 연동은 현 단계 범위에서 제외)* | High |
| **FR-SH-06** | `BR-01`, `BR-02` | **대화 의도 연동**: 기존 `IntentClassifier`에 스마트홈 조회/차단 의도를 추가하여 "가스불 확인해줘", "가스불 꺼줘" 등의 발화를 처리하고 기존 의도(`status`, `emergency` 등) 분류 정확도를 해치지 않는다. | High |
| **FR-SH-07** | `BR-01`, `BR-02` | **GUI 스마트홈 제어 탭**: Tkinter UI에 `5단계 · 스마트홈` 탭을 추가하여 ① 현재 가스밸브 상태·개방 시간 표시, ② 시뮬레이션 상태 주입(가스 열림/경과 시간/통신 장애 토글), ③ 가스 차단·상태 조회·안전 점검 버튼을 제공한다. | High |
| **FR-SH-08** | `BR-02`, `BR-06` | **로컬 알림 로그 연동**: 가스 차단 실행, 장시간 개방 경고, 통신 실패/차단 실패 발생 시 기존 `AlertService`를 통해 로컬 알림 기록(`LOCAL_SIMULATION_ONLY`)을 남긴다. | High |
| **FR-SH-09** | `BR-01`, `BR-05` | **독립 네임스페이스 상태 영속화**: 스마트홈 상태(밸브 상태, 마지막 갱신 시각, 개방 시간, 시뮬레이션 설정)를 `companion_state.json` 내 독립 키(`"smart_home"`)에 저장하고 재실행 시 복원한다. | High |

### 3.2 복약 리마인더 고도화 (`FR-MED` — 타 팀원 구현 대상, 문서화 전용)

> **담당 구분 안내**: 본 기능은 **3번 개발자의 구현 담당이 아니며**, 프로젝트 전체 문서화 완성도 및 타 팀원·AI 에이전트 협업을 위해 PRD 수준으로 우선 정의한 요구사항이다.

* **배경 (기존 코어 대비 확장 지점)**: 현재 `companion_robot.py`의 `MedicationManager`는 약 이름과 24시간제 `HH:MM`을 등록하고 예정 시각부터 15분 이내 확인 시 1일 1회 알림을 기록한다. 고령자 복약 순응도를 높이기 위해 복용 여부 확인·재알림(스누즈)·미복용 이력 추적 및 경고 알림으로 확장한다.

#### 핵심 유스케이스 (`UC-MED-01` ~ `UC-MED-03`)

| ID | 유스케이스명 | 사전 조건 | 기본/예외 흐름 | 사후 조건 |
| :--- | :--- | :--- | :--- | :--- |
| **UC-MED-01** | 예정 시각 복약 리마인드 알림 | 복약 일정 등록 완료 | 예정 시각 도래 시 대화/음성 안내 및 키오스크 리마인더 팝업·로그를 출력하고 상태를 `PENDING`으로 표시 | 복약 대기 상태(`PENDING`) 기록 |
| **UC-MED-02** | 복용 완료 확인 및 미응답 재알림 | 복약 상태 `PENDING` | 사용자가 "약 먹었어" 발화 또는 `복용 완료` 버튼 클릭 시 `TAKEN` 기록. 미응답 시 설정 간격(예: 10~15분)마다 최대 N회 재알림 수행 | `TAKEN` 확정 또는 재알림 카운트 증가 |
| **UC-MED-03** | 반복 미복용 경고 알림 | 최대 재알림 횟수 초과 | 최종 확인 시점까지 복용 확인이 없으면 상태를 `MISSED`로 전환하고 `AlertService`에 보호자/로컬 경고 알림 생성 | `MISSED` 이력 저장 및 로컬 경고 기록 |

## 4. 비기능 요구사항 (`NFR-SH`)

| ID | 분류 | 요구사항 명세 | 검증 방법 |

| **NFR-SH-01** | 모듈성 / OOP | Smart Home 로직은 `smart_home/` 독립 패키지로 분리하며, 제어기는 구체 클래스가 아닌 추상 인터페이스(`SmartDevice`, `SmartHomeApiClient`)에 의존한다(DIP). 기존 `companion_robot.py` 수정은 `MODULE_INTEGRATION_GUIDE.md` 규약 내 최소 진입점 연결로 제한한다. | 코드 리뷰 및 패키지 import 구조 확인 |
| **NFR-SH-02** | 하위 호환성 | 기존 `test_companion_robot.py`의 8개 단위 테스트가 코드 수정 없이 전부 통과해야 한다. | `python -m unittest -v` 실행 |
| **NFR-SH-03** | 안전성 (Fail-Safe) | 차단기 어댑터 통신 오류, 미등록 기기, 잘못된 명령이 입력되더라도 GUI나 로봇 대화 루프가 중단되지 않으며, 사용자 친화적 오류 안내와 로컬 경고 로그를 남긴다. | 장애 주입 단위 테스트 |
| **NFR-SH-04** | 테스트 가능성 | 외부 실서버·인터넷·실물 센서 없이 표준 라이브러리 `unittest`만으로 모든 정상/예외/경계 테스트를 결정적으로 실행할 수 있어야 한다. (외부 라이브러리는 상업용 허용 OSS에 한해 필요 시 선택 도입) | 오프라인 환경 테스트 실행 |
| **NFR-SH-05** | 시뮬레이션 명시성 | GUI, 대화 응답, 알림 로그에 실제 물리 밸브 제어 및 외부 긴급 발신이 아님(시뮬레이션)을 명확히 표기한다. | UI 텍스트 및 응답 문자열 확인 |

## 5. 기술 결정 기록 (ADR 요약): IoT vs OCR

* **검토 배경**: `README.md`에 검토 옵션으로 기록된 "OCR 기반 가스 잠금 확인"과 "IoT 기반 밸브 잠금 확인 및 제어" 중 1차 구현 방식을 선정해야 함.
* **결정**: **IoT 가스밸브 상태 확인 및 자동 차단 시뮬레이션 방식을 1차 표준으로 채택**한다.
* **근거**:
  1. IoT 가스밸브 자동 차단기는 상태 확인뿐 아니라 **실제 차단 명령(`가스차단`)**까지 단일 흐름으로 지원하며, B2C 렌탈 패키지(월 43,900원) 모델(`BR-03`)과 부합한다.
  2. 결정적 상태 전이(`OPEN` ↔ `CLOSED`, `ERROR`, `OFFLINE`) 기반으로 테스트 케이스 작성이 명확하고 안정적이다.
* **확장 여지**: 향후 카메라 영상 기반 OCR 확인 기능이 추가되더라도, 동일한 `SmartDevice` 인터페이스 또는 보조 검증 어댑터로 결합할 수 있도록 인터페이스를 열어 둔다.
