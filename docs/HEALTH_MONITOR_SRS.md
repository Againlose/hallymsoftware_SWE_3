# SRS — 4번 Health Monitoring (v0.1)

## 목적과 범위
사용자 또는 시연자가 측정값을 수집하고 최근 상태와 이력을 확인한다. 연속된 기준 범위 이탈은 사용자·보호자 역할별 로컬 알림으로 기록한다. 본 모듈은 의료기기, 진단 또는 응급 대응 서비스가 아니다.

| ID | 요구사항 | 인수 기준 |
|---|---|---|
| HM-F01 | 교체 가능한 웨어러블 입력 | Mock 또는 로컬 JSON 샘플을 같은 포트로 수집. 타임존 누락, 범위 밖 값, 중복·역순, 300초 초과 과거, 10초 초과 미래 기록은 거부 |
| HM-F02 | 상태와 이력 확인 | 마지막 측정의 시간·심박·SpO₂·시연 판정 및 최근 최대 100건 표시 |
| HM-F03 | 이상 징후 규칙 | 심박 <50 또는 >110 bpm, SpO₂ <92% 중 하나에 해당하는 샘플이 120초 이내에 연속 두 건이면 알림 생성. 정상 샘플 이후 재발 시 다시 생성 |
| HM-F04 | 역할별 알림 | `건강/사용자`, `건강/보호자` 각 1건. 외부 발신 없음 |
| HM-F05 | 저장 및 복원 | `health_monitor` 예약 키로 직렬화. 누락·null은 빈 상태로 시작 |
| HM-F06 | DUR 보조 조회 | 제품명 조회는 웨어러블 판정과 독립. 기본 Mock, 명시적 옵션에서만 실 API 호출. 결과 없음은 안전 판정이 아님 |
| HM-N01 | 비밀정보 보호 | 키는 환경 변수에서만 읽고 저장·출력·커밋하지 않음. DUR에 건강 측정값이나 사용자 식별자를 전송하지 않음 |
| HM-N02 | 오프라인 검증 | 표준 라이브러리와 Mock을 사용해 네트워크 없이 단위 테스트 실행 |

직접 BLE·제조사 API 연결, 자동 백그라운드 수집, SMS/119 발신은 이번 범위에서 제외한다. 기준값은 데모 상수이며 사용자별 기준, 연속 수집 가용성 및 실제 기기 검증은 별도 설계가 필요하다. 건강 이력은 로컬 평문 상태이므로 시연에는 합성 데이터만 사용한다.

## 사용자 시나리오와 실패 인수 기준

| 시나리오 | 시작 조건과 입력 | 기대 결과 |
|---|---|---|
| UC-01 정상 수집 | 탭 열기 → 최신 합성 샘플 수집 | 시연 기준 범위 내, 타임스탬프·단위 표시; 알림 0건 |
| UC-02 연속 이탈 | 120초 이내 이탈 샘플 3개를 순서대로 수집 | 두 번째에서 역할별 1건, 세 번째에서 추가 없음 |
| UC-03 기기 입력 중단 | 동일 스냅샷 재수집, 파일 없음 또는 깨진 JSON | 잘못된 값을 새 이력으로 기록하지 않음; 사용자에게 수집 오류 표시 |
| UC-04 과거 이력 조회 | 마지막 승인 샘플이 300초 초과 경과 | `오래된 기록 · 현재 상태 알 수 없음` 표시(다음 화면 갱신 시) |
| UC-05 저장 복원 | 구버전 상태 파일 또는 현재 건강 이력 포함 상태로 시작 | 기존 코어 키를 유지하고 누락 키/`null`은 빈 상태 처리 |
| UC-06 DUR 실패 | 키 없음, 네트워크 또는 승인 오류 | 건강 수집은 독립적으로 동작; 조회 실패 메시지는 키 및 요청 URL 미포함 |

## 운영 적용 완료 조건 (이번 제출에는 포함되지 않음)

- 실기기 SDK/브리지 연속 수집과 시각·센서 품질 검증, 의료 기준 검토.
- 사용 동의, 저장 암호화·접근 제어, 보존·삭제 정책 수립. 팀 상태 파일에 실제 건강 정보를 저장하지 않는다.
- 외부 보호자 연락은 팀의 로컬 전용 정책을 변경하는 별도 기능으로, 승인·수신 확인·감사 및 재시도 설계가 선행되어야 한다.
