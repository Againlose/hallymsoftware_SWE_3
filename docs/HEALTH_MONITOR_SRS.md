# SRS — 4번 Health Monitoring (v0.1)

## 목적과 범위
사용자 또는 시연자가 측정값을 수집하고 최근 상태와 이력을 확인한다. 연속된 기준 범위 이탈은 사용자·보호자 역할별 로컬 알림으로 기록한다. 본 모듈은 의료기기, 진단 또는 응급 대응 서비스가 아니다.

| ID | 요구사항 | 인수 기준 |
|---|---|---|
| HM-F01 | 교체 가능한 웨어러블 입력 | Mock 또는 로컬 JSON 샘플을 같은 포트로 수집. 타임존 누락, 범위 밖 값, 중복·역순 기록은 거부 |
| HM-F02 | 상태와 이력 확인 | 마지막 측정의 시간·심박·SpO₂·시연 판정 및 최근 최대 100건 표시 |
| HM-F03 | 이상 징후 규칙 | 심박 <50 또는 >110 bpm, SpO₂ <92% 중 하나에 해당하는 샘플이 연속 두 건이면 알림 생성. 정상 샘플 이후 재발 시 다시 생성 |
| HM-F04 | 역할별 알림 | `건강/사용자`, `건강/보호자` 각 1건. 외부 발신 없음 |
| HM-F05 | 저장 및 복원 | `health_monitor` 예약 키로 직렬화. 누락·null은 빈 상태로 시작 |
| HM-F06 | DUR 보조 조회 | 제품명 조회는 웨어러블 판정과 독립. 기본 Mock, 명시적 옵션에서만 실 API 호출. 결과 없음은 안전 판정이 아님 |
| HM-N01 | 비밀정보 보호 | 키는 환경 변수에서만 읽고 저장·출력·커밋하지 않음. DUR에 건강 측정값이나 사용자 식별자를 전송하지 않음 |
| HM-N02 | 오프라인 검증 | 표준 라이브러리와 Mock을 사용해 네트워크 없이 단위 테스트 실행 |

직접 BLE·제조사 API 연결, 자동 백그라운드 수집, SMS/119 발신은 이번 범위에서 제외한다. 기준값은 데모 상수이며 사용자별 기준, 샘플 최대 간격 및 최신성 보장은 별도 설계가 필요하다. 건강 이력은 로컬 평문 상태이므로 시연에는 합성 데이터만 사용한다.
